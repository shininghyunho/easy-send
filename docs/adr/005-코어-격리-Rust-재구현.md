# ADR-005: 프로토콜 코어를 순수 패키지로 격리했다가, Rust로 통째 교체한다

- **상태**: 확정 (격리 2026-08-15 설계 시점, Rust 교체 완료 2026-08-16)
- **결정**: 프로토콜 구현(탐색·전송·보안)을 처음부터 Flutter 의존이 전혀 없는 순수 Dart 패키지(`easy_send_core`)로 격리하고, UI(`app/`)는 그 API만 소비한다. Phase 3에서 이 경계를 그대로 잘라 Rust 크레이트(`app/rust/`)로 재구현하고 flutter_rust_bridge(FRB — Rust 함수를 Dart에서 호출하게 해주는 바인딩 생성기)로 연결했다. 구 Dart 코어는 `archive/dart-core` 브랜치에 참조용으로만 보존한다.
- **대가**: 격리 규칙(코어에 Flutter API 금지)을 lint로 강제하는 관리 비용. Rust 교체 후에는 빌드에 Rust 툴체인이 추가로 필요하다.

## 배경

Rust 교체는 처음부터 로드맵에 있었다(Phase 3). 문제는 "나중에 교체할 수 있는 구조를 지금 어떻게 만들 것인가"였다. UI 코드와 프로토콜 코드가 섞이면, 교체 시점에 무엇이 프로토콜이고 무엇이 UI인지부터 다시 발라내야 한다.

## 검토한 대안 — 격리 방식

### ① 앱 안에 그냥 구현, 교체 때 분리 — 기각

**기각 이유: 경계는 나중에 그으면 이미 늦다.** Riverpod(상태관리)·Flutter 플랫폼 API가 프로토콜 로직에 스며드는 것은 막는 비용보다 되돌리는 비용이 훨씬 크다.

### ② 순수 Dart 패키지로 선격리 — 채택

`easy_send_core`는 `dart:io`까지만 쓰고 Flutter·Riverpod 의존을 lint로 금지했다. Riverpod은 `app/`에서 코어 클래스를 감싸는 용도로만 사용. 이 절단면(탐색/전송/보안/모델)이 그대로 Rust 크레이트의 모듈 구조가 됐고, Go CLI(ADR-006)도 같은 절단면으로 구현됐다.

## 검토한 대안 — 교체 진행 방식

### 일괄 교체 (빅뱅) — 기각

코어 재구현과 앱 연결을 한 번에 하는 안. **기각 이유: 실패 시 원인 지점을 못 찾는다.** FRB 통합·Rust 재구현·Android 크로스컴파일이라는 독립 리스크 3개가 한 덩어리로 묶인다.

### 리스크 분리 순차 (P3-0 → P3-1 → P3-2 → P3-3) — 채택

1. **P3-0 스파이크**: FRB로 Rust 함수 호출 왕복이 mac·Android 실기기에서 되는지만 검증. Android NDK 크로스컴파일 함정을 여기서 해소.
2. **P3-1 코어 재구현**: 앱은 건드리지 않고 Rust 크레이트만 완성. 같은 크레이트의 CLI 바이너리로 Go CLI·Dart 코어·실기기 앱 3상대와 상호 전송을 체크섬 일치로 실증 — 앱 연결 전에 프로토콜 정확성을 독립 확인.
3. **P3-2 브리지 이식**: 앱의 Dart 코어 의존을 FRB 경유 Rust 코어로 교체. 승인 다이얼로그(Rust 서버 → Dart UI 콜백)와 이벤트 스트림이 이 단계의 핵심 경계.
4. **P3-3 실기기 검증**: Android 회귀(MediaStore·MulticastLock)와 소켓 자기복구(앱 freeze 재개, Wi-Fi 토글로 IP가 바뀌어도 회복)까지 확인.

각 단계가 독립적으로 PASS/FAIL 판정되어, 문제가 나면 원인 층이 바로 특정된다.

## 결과

**얻는 것**

- "격리 → 재구현 → 스위치"가 계획대로 동작했다. UI 코드는 타입 매핑 수준의 변경만으로 코어가 통째로 바뀌었다.
- 프로토콜 스펙(PRD 4장) 하나로 Dart·Go·Rust 3개 구현이 상호 운용됨을 실증 — 스펙과 격리 경계가 모두 실전 검증됐다.

**잃는 것·지켜야 할 것 (감수)**

- 빌드 사전 조건 증가: Rust 툴체인(+Android는 NDK, cargo-ndk)이 필요하다.
- rustls는 ring 백엔드로 고정해야 한다(`default-features = false`) — 기본 aws-lc-rs는 CMake를 요구해 NDK 크로스컴파일이 깨진다. rcgen·tokio-rustls·hyper-rustls도 같은 백엔드로 정렬 유지.
- 구 Dart 코어는 master에서 제거됐다. 참조가 필요하면 `archive/dart-core` 브랜치를 본다.
