# ADR-004: 신뢰 모델은 TOFU(PIN 없음)로 하고, 인증서 지문이 곧 기기 ID다

- **상태**: 확정 (2026-08-15)
- **결정**: 기기 신원은 인증서 지문(인증서 DER 바이트의 SHA-256, hex 64자리) 하나로 통일한다 — 별도 UUID 없음. 신뢰는 TOFU(Trust On First Use — 최초 연결 때 사용자가 직접 확인하고, 이후엔 저장된 지문과 비교) 방식이며 PIN 입력은 없다.
- **대가**: 앱을 재설치하면(인증서 재생성) 같은 기기가 "새 기기"로 보인다. 능동적 공격자가 최초 연결 순간에 끼어드는 것은 사용자 확인 외엔 막을 수 없다.

## 배경

자체서명 HTTPS(ADR-003)는 채널을 암호화하지만 "지금 연결된 상대가 누구인가"는 보장하지 않는다 — CA(인증기관)가 없으니 아무나 인증서를 만들 수 있기 때문이다. 신원 보장을 어떻게 할지, 그리고 기기를 무엇으로 식별할지를 정해야 했다.

전제가 하나 있다: **이 앱은 개인 소유 기기끼리만 쓴다.** 낯선 사람과 파일을 주고받는 시나리오(LocalSend의 공용 Wi-Fi 사용)는 비목표다. 최초 연결 순간에 두 기기가 모두 사용자 손안에 있으므로, "처음 한 번은 사람이 직접 확인한다"가 현실적으로 가능하다.

## 검토한 대안 — 신뢰 방식

### ① 암호화만, 신원 검증 없음 — 기각

TLS로 도청만 막고 상대 확인은 생략하는 안. **기각 이유: 목록 위장이 가능해진다.** 탐색은 암호화되지 않은 UDP라서, 악의적 기기가 남의 alias를 흉내 내 목록에 나타나면 사용자가 구분할 방법이 없다.

### ② TOFU + PIN — 기각

최초 연결 때 양쪽 화면에 PIN을 띄워 대조까지 시키는 안(SSH 지문 대조와 같은 원리). 보안은 가장 강하다. **기각 이유: 개인 기기 전제에서는 비용 대비 이득이 없다.** 두 기기가 모두 내 손에 있으면 "지금 내 폰에서 요청 다이얼로그가 떴는가" 자체가 그 확인이다. PIN은 매 최초 연결마다 마찰만 더한다.

### ③ TOFU, PIN 없음 — 채택

각 기기가 `(지문, alias, 최초 승인 시각)` 목록을 로컬에 저장한다. 신뢰 목록에 없는 지문이 오면 승인 다이얼로그에 **"새 기기"** 뱃지를 띄우고, 사용자가 승인하면 저장된다. 승인 다이얼로그 자체는 알던 기기여도 항상 뜬다(수신 동의는 신뢰와 별개 결정).

## 검토한 대안 — 기기 식별자

### UUID 별도 유지 — 기각 (설계 중 철회)

처음엔 "기기 ID = UUID, 인증서는 채널용"으로 값 2개를 두려 했다. **철회 이유: UUID는 검증 불가능한 자기 주장이다.** UDP announce의 UUID는 누구나 복제할 수 있다. 반면 인증서 지문은 TLS 핸드셰이크에서 개인키 보유를 증명해야 제시할 수 있으므로, 위조하려면 개인키까지 훔쳐야 한다. 검증 가능한 값이 이미 있는데 검증 불가능한 값을 하나 더 관리할 이유가 없다.

### 지문 = 기기 ID — 채택

연결 시 검증이 2단계가 된다.

1. **채널 무결성**: TLS에서 상대가 실제 제시한 인증서의 지문을 계산해, 탐색에서 광고한 지문과 일치하는지 확인. 불일치면 즉시 연결 종료. 이것이 "목록에서 고른 기기"와 "실제 연결된 기기"가 같음을 보장한다.
2. **TOFU 신뢰 목록**: 그 지문이 아는 기기인지 조회해 새 기기/알던 기기를 표시.

구현 주의: 지문을 고정(pinning)하더라도 TLS 핸드셰이크의 서명 검증은 유지해야 한다. CA 검증만 생략하는 것이지, 서명 검증까지 끄면 인증서만 복제한 중간자를 못 막는다(Rust 코어에서 커스텀 검증기로 이 구분을 실증).

## 결과

**얻는 것**

- 신원 값이 하나뿐이라 스키마·저장·비교 로직이 전부 단순하다. 언어가 다른 피어(Dart RSA, Go·Rust EC P-256)끼리도 지문 비교만으로 상호 인증됨을 실증했다 — 키 종류가 달라도 무관.
- 개인 기기 전제에서 필요한 만큼의 보안을 마찰 없이 달성.

**잃는 것 (감수)**

- 앱 재설치 = 인증서 재생성 = "새 기기"로 재승인. 신뢰 목록에 옛 지문이 남는다(설정에서 수동 삭제).
- "아는 기기의 지문이 바뀌었다"는 경고는 원리상 불가능하고 "새 기기" 표시로 대체된다.
